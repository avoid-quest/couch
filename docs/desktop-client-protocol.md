# Bundled desktop client protocol

The desktop window always loads Couch's bundled assets. In **This computer** it uses the local host token and exact frontend build identity. In **Another Couch** it uses only the selected address and that address's paired Controller or Administrator token. The local playback host is stopped; a separate loopback maintenance coordinator remains available for this installation's updates.

`desktopClientProtocol` in the public `/api/connection` response is the compatibility version. Version 1 covers the HTTP endpoints used by the desktop client, pairing and role responses, WebSocket commands, results and session state. A bundled client checks this field without a token before it sends a stored pairing. For a matching version it opens `/api/ws?clientProtocol=1`; the server accepts different app build revisions from the bundled Tauri origin. Browser pages still send their exact `build` key and retain exact asset/server matching. Missing or different protocol versions stop before the client sends its pairing and show update and target-switch guidance.

Keep changes to version 1 additive: preserve existing fields, meanings, authorization rules and WebSocket messages for older clients. Bump the protocol on both sides when a required field or command changes incompatibly, and test an older and newer app revision against the new server. The marker is a compatibility claim, not an authorization grant. Every HTTP request and WebSocket still requires the selected host's own pairing and current role; revocation closes the socket. Pairings are stored by exact selected origin and checked against the public installation ID before use. Changing a host at the same address requires pairing again.

During staged upgrades the host also advertises the older `desktopRemoteUi: 1` marker. Old clients use that marker to open the host-served page in their remote window and continue to use exact build matching; the bundled single-window client uses `desktopClientProtocol`. Remove the legacy marker only after those clients are no longer supported.

The bundled page's [Tauri CSP](https://v2.tauri.app/security/csp/) allows HTTP(S) and WebSocket connections to user-selected LAN targets because its configuration is static. The server still checks Host and Origin, paired authority and LAN policy. Native commands remain limited to the bundled `main` window; local media and metadata commands also require **This computer**. In **Another Couch**, the main window reports real input through a native command to this installation's loopback maintenance coordinator. The selected host's session reports its own activity with its paired token. Plain HTTP LAN transport and target-machine webview behavior need platform qualification.
