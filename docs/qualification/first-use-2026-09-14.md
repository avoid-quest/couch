# First-use implementation and verification

The implementation follows the accepted [UX review](https://github.com/avoid-quest/couch/issues/260#issuecomment-5667781876), [source journey](https://github.com/avoid-quest/couch/issues/259#issuecomment-5666511323), and [operating-mode decision](https://github.com/avoid-quest/couch/issues/258#issuecomment-5667095900). The disposable prototype was inspected as a behavior reference. Its fixture implementation was not merged.

## Implemented behavior

- Home combines search or pasted links, default avoid radio, and direct source browsing. Saved, Up next and Settings remain in the navigation. Legacy Search and Browse URLs preserve their queries and open Home.
- Filters show matching source groups and counts. Pasted links bypass filters. Source-specific setup and reconnect actions open existing forms in one dialog and preserve the query and focus when closed.
- Play now moves the selected item or album ahead of waiting entries and retains their order. Add to queue appends without autoplay. The existing queue/cursor transaction saves ordering and progress together.
- The current playback bar opens Now playing, including provider programme details, actual transport capabilities, volume and queue. Failed playback keeps recovery reachable. Back restores browsing and focus, including after Stop removes the bar.
- avoid radio uses the existing playlist parser, persistent station identity and Couch queue/favorites. Home and active playback share provider metadata retrieval. Expired programme data disappears even if the next network request fails. Explicit search retries refresh once.
- Native first launch chooses This computer or Another Couch. First local use asks about sharing, off by default. The local app manages all settings without an administrator remote. Only the local host changes sharing; disabling it disconnects remotes while retaining pairings and local playback.
- The first remembered remote becomes Administrator. Later pairings become Controllers, even when no remembered Administrator remains. Local management can grant administration or forget any remote.
- The native Play on popover marks the current computer and remembers target addresses. Switching away from active local playback or enabled sharing requires an interruption confirmation. Local shutdown waits for the sidecar and native player before opening a remote.
- App remote mode loads the target's UI in a separate Tauri window without native capabilities. The trusted local window retains device selection and recovery. Target entry checks a LAN origin, rejects redirects and unsupported desktop-remote UI contracts, and keeps exact frontend/server build checks intact. Remote mode never silently starts the local backend.
- Browser pairings stay bound to their origin and installation identity. Advertised addresses do not receive saved credentials automatically. An installation replaced at the same address requires pairing again.

The general design-system rule is in `AGENTS.md`. Existing shadcn components supply dialogs, tabs, buttons and the device popover. Switch and Empty were added from the official catalog. The only new presentation adjustments address concrete gaps: WebKit's duplicate search-clear button, native dialog width at Couch's TV text size, and playback layout/focus behavior.

## Results

- `bun run check` passed: TypeScript and 1,162 tests, with nine opt-in integration tests skipped and no failures.
- The final native build succeeded. Rust tests: 36 passed, one pre-existing ignored test.
- Focused final recovery checks: 79 passed, covering Home, radio expiry and retry, device selection, Now playing, and credentials tied to their origin.
- Real browser walkthrough at desktop and 390 px phone width: first pairing became Administrator, default radio returned ten stations and real programme data, queue-only addition stayed idle, live RaiPlay/Twitch/radio-directory search results remained usable when YouTube failed, and source setup preserved query and focus.
- Native walkthrough: fresh local startup kept sharing off, private local Home needed no phone, Add to queue retained its station, and Play now started Lyl Radio through the native player. Expanded Now playing displayed the programme and current track, Stop/Next/volume, and the earlier Sygma Radio entry in Up next. Escape returned from the existing listening view to browsing.

The first complete suite run after fixture updates had one display-session timeout waiting one second for a child process under concurrent build load. The unchanged display-session file passed all four tests on rerun. The subsequent complete `bun run check` passed, including that display-session file.

## Rollout boundaries

This is implementation and local verification, not a release or platform qualification. No PR was merged, no release was produced, and the T480 was not used to build or run these changes. The retired qualification campaign was not restarted.

Debian 13 installation and dependency provisioning remain blocked by the [fresh-machine evidence](https://github.com/avoid-quest/couch/issues/263#issuecomment-5668286598). The retained installer rejects Debian; the minimal guest also lacks `fusermount`. [Issue #265](https://github.com/avoid-quest/couch/issues/265) owns the installation/dependency policy, address mechanism, and mode-aware update acceptance. This implementation preserves existing local AppImage trial checks and directs an unfinished trial to local mode rather than weakening acceptance.

The X11 preview verifies application behavior with virtual output. It does not qualify physical audio/video devices, hardware decoding, CEC, arbitrary webview versions, or Debian desktop/appliance operation. YouTube returned its existing provider failure in the live browser search, so successful YouTube playback is not claimed. No TLS, new domain provisioning, or proof-of-concept migration was added. Native LAN entry validation is not an OS firewall; the webview performs its own DNS resolution after preflight.
