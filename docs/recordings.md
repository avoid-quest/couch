# Completed recordings

Couch records a selected future guide programme through Tvheadend's HTTP DVR API. Guide imports remain the source of channel and airing identity. An administrator maps the exact source, channel and tvg-id to an enabled backend channel with an assigned service. Scheduling uses the selected programme's UTC times, not an unverified backend event match.

Use Tvheadend API 20 or newer with HTTP Basic authentication enabled over HTTPS, or HTTP on loopback. The recorder account needs WebUI, Basic DVR and Failed view access, the selected DVR profile, and the mapped channels. The separate playback account needs WebUI, streaming, Basic DVR, View all and Failed view access. It must not own these recordings, have administrator access, or have Manage all DVR access. Keep these account identities and rights stable while Couch uses the backend.

Couch verifies resolved usernames and basic DVR access during setup and scheduling. Setup also checks that the backend clock agrees with Couch within one minute. It creates one disabled entry with elapsed times and explicit one-minute padding, then requires that exact entry in the backend's failed-recording listing through both accounts. A UUID-only playback write must return HTTP 403. Couch deletes the exact permission-check entry and confirms its absence before saving the qualified configuration revision. The padded stop time is already elapsed, and `enabled:false` independently prevents capture. The entry can briefly appear among failed recordings as "Couch recording permission check".

Couch saves the private permission-check intent before sending it. A lost create response is reconciled by its exact marker, owner, channel and times; it is never automatically resubmitted. Missing or duplicate identity, changed enabled/padding fields, media files, or unconfirmed cleanup blocks setup. Retrying setup continues the saved verification and cleanup, including after Couch restarts. If the recorder lacks Failed view, the backend can hide the disabled entry even from its owner and deny deletion. Setup remains blocked until the account permissions are corrected and the same intent can be reconciled. Couch does not request administrator credentials to bypass this restriction. A request that never appears on the backend remains unconfirmed and requires backend investigation.

Ordinary programme scheduling uses the qualified configuration revision and current account/profile/channel checks without creating another temporary entry. Setup saved before failed-record permission qualification must be verified again. An interrupted older future-entry check first finishes its own cleanup; a new failed-entry check must then pass before setup becomes qualified.

DVR listings are filtered to the recorder owner before the backend computes their total. Couch still requires the complete matching list, at most 1,000 entries, and checks every returned owner exactly. The backend's string filter is an anchored, escaped, case-insensitive regular expression, so usernames that differ only by letter case can cause setup or reconciliation to fail. Unrelated owners are outside this listing; hidden matching rows, malformed responses and truncated totals remain errors. Real mixed-owner qualification of this correction remains pending.

Playback uses the existing native player. Before resolving the private recording URL, Couch checks completed state and requires a UUID-only save permission probe to fail with HTTP 403. This request supplies no mutable recording properties. Its write check covers the same permission used by Tvheadend's [HTTP final-segment reporter](https://github.com/tvheadend/tvheadend/blob/f7f114e9b7d80e4b32b2f708c8520e2a414a2533/src/webui/webui.c#L2547) and [recording ownership check](https://github.com/tvheadend/tvheadend/blob/f7f114e9b7d80e4b32b2f708c8520e2a414a2533/src/dvr/dvr_db.c#L184). Couch keeps profile progress from native observations and does not write backend watched fields. Changing backend permissions during a transfer can invalidate this policy.

The local job UUID and selected airing snapshot commit before submission and broadcast. The private backend comment carries that UUID for later reconciliation. It is not a backend idempotency key. Couch never automatically repeats an ambiguous create request. A job remains Checking until the backend confirms its identity; refreshing or restarting Couch reconciles it without another create. Overlapping schedule requests for the same Couch channel return the existing job, including when a later guide import changes its start identity.

Cancellation records intent and then checks a complete successful backend listing for absence. A lost HTTP response alone does not confirm cancellation. Backend status updates preserve the first observed recording failure cause. An unavailable or incomplete backend keeps the last confirmed state with an error. Completed recording playback and backend recording activity have separate lifetimes.

The current bounded store supports one backend identity, 256 channel mappings and 500 retained jobs. Credentials can be replaced with an expected setup revision. Once jobs exist, backend/account/profile identity changes are rejected so existing jobs cannot be silently rebound to another service. Mapping edits use revisions; existing job snapshots stay intact.

## Setup permission correction

The initial real-backend run used correctly configured accounts. It did not test an empty backend library with missing View all rights or an incorrectly writable playback account. A later run qualified the pending-entry setup check on reviewed source `65fac90eb918349257aa9aca63632fd957842fc0`. It used the same cached official image, one owned container/network, one CPU, 768 MiB memory with no extra swap, 128 PIDs and only loopback port 26991. First start was 2026-09-06 22:35:19.1624 UTC and cleanup finished at 22:35:23.253, within a 300-second window that reserved 60 seconds for cleanup.

Missing View all and Manage all each produced HTTP 409; correct pending-entry permissions produced HTTP 200. Each case created one disabled future entry, no Couch job or captured media, and confirmed an empty backend after cleanup. A lost create response plus held cleanup blocked setup. Couch/backend restart preserved the exact disabled UUID; retry cleaned it without another create. The source archive and 167 extracted files matched before and after the run. The container exited 0 without OOM, exact structured checks confirmed container/network absence, and generated credentials and private databases were removed.
