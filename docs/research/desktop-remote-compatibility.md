# Desktop remote compatibility across Couch versions

Research for [Verify desktop remote compatibility across Couch versions](https://github.com/avoid-quest/couch/issues/267), 14 September 2026. Source baseline is Couch commit `34757770ebe02ff5de1ccebb8a68944f35c86968`. This answers the design question for [Decide who installs and updates every Couch dependency](https://github.com/avoid-quest/couch/issues/265). It does not implement remote mode or qualify a native release.

## Recommendation

Use the selected installation's server-delivered browser remote UI in a separate Tauri `WebviewUrl::External` window. Keep the bundled local selector and native recovery controls under the app's ownership. Pair through the selected installation using browser roles. Preserve exact build matching between that installation's UI and backend. The app remote's own Couch release need not equal the playback computer's release.

This is a supported Tauri mechanism, with implementation prerequisites below. Tauri accepts external HTTP and HTTPS URLs; its pinned source passes an external URL through to the runtime. Keep `frontendDist` bundled. Setting the selected server as `frontendDist` or `devUrl` would also change the origin Tauri considers local. [Tauri configuration](https://v2.tauri.app/reference/config/#webviewurl), [pinned URL preparation](https://github.com/tauri-apps/tauri/blob/tauri-v2.11.5/crates/tauri/src/manager/webview.rs#L430-L478), [pinned local-origin classification](https://github.com/tauri-apps/tauri/blob/tauri-v2.11.5/crates/tauri/src/webview/mod.rs#L1698-L1733).

The product contract requires one complete app, a stopped local playback backend in remote mode, explicit return to local mode, and LAN access without initial TLS. The native baseline remains Debian 13 x86_64 with X11. [Agreed local and remote modes](https://github.com/avoid-quest/couch/issues/258#issuecomment-5667095900).

## Evidence and comparison

The checkout pins Rust Tauri `2.11.5`, `tauri-runtime` `2.11.3`, vendored `tauri-runtime-wry` `2.11.4`, Wry `0.55.1`, and `tauri-utils` `2.9.3`. JavaScript API is `2.11.1`, CLI `2.11.4`. The runtime has a local Cargo patch, so upstream documentation alone is insufficient. Its URL and initialization-script forwarding still use Wry's first-class builder methods. [Cargo manifest](https://github.com/avoid-quest/couch/blob/34757770ebe02ff5de1ccebb8a68944f35c86968/src-tauri/Cargo.toml), [lockfile](https://github.com/avoid-quest/couch/blob/34757770ebe02ff5de1ccebb8a68944f35c86968/src-tauri/Cargo.lock), [JavaScript pins](https://github.com/avoid-quest/couch/blob/34757770ebe02ff5de1ccebb8a68944f35c86968/package.json), [vendored runtime](https://github.com/avoid-quest/couch/blob/34757770ebe02ff5de1ccebb8a68944f35c86968/src-tauri/vendor/tauri-runtime-wry/src/lib.rs#L4816-L4828).

| Question | Server-delivered UI | Bundled remote UI |
| --- | --- | --- |
| Independently updated computers | Target supplies its own UI and backend together. Shell compatibility depends on web features and a small remote-entry contract. | Old UI talks to a newer backend or the reverse. Requires an explicit supported protocol range and compatibility tests. |
| Existing exact build check | Retain it. Reload fetches the target's current assets after an update. | Reload fetches the same bundled assets. It cannot repair an unequal build. |
| Network origin | UI, pairing, API and WebSocket use the target origin, matching browser behavior. | Cross-origin API/WebSocket traffic needs CSP changes, server origin policy and transport qualification. |
| Recovery | Native/local controls remain available if the remote page fails. | Bundled controls can show failure, provided mode selection is separated from the session. |
| Update ownership | Target owns its UI/backend pair. App remote owns its native shell/runtime and its dormant local installation. | App remote also owns a protocol client that must remain compatible with independently updated targets. |

These conclusions follow from Couch's current build identity and transport behavior. `buildKey` contains `version:revision:dataFormat`; a missing revision disables the key, which is a development escape rather than release compatibility. The build script embeds matching metadata into the standalone frontend and the sidecar's frontend. Packaged WebSocket connections require an exact key, including revision. Equal marketing versions therefore do not imply compatibility. [Build identity](https://github.com/avoid-quest/couch/blob/34757770ebe02ff5de1ccebb8a68944f35c86968/src/shared/build.ts), [build generation](https://github.com/avoid-quest/couch/blob/34757770ebe02ff5de1ccebb8a68944f35c86968/scripts/build.ts), [WebSocket admission](https://github.com/avoid-quest/couch/blob/34757770ebe02ff5de1ccebb8a68944f35c86968/src/server/hub.ts#L371-L387).

The authenticated `/api/build` check currently reloads once per target build using `sessionStorage`, then exposes `build-mismatch`. Keep that guard for assets fetched from the selected target. A changed backend during a session should reconnect and reload that same target, preserve pairing, and stop with an actionable mismatch if assets remain stale. A bundled alternative would require replacing this exact-key admission with a separately defined API contract covering messages, state, pairing and roles. There is no such range today; adding one is unnecessary for the recommended path. [Session implementation](https://github.com/avoid-quest/couch/blob/34757770ebe02ff5de1ccebb8a68944f35c86968/src/client/session.ts#L53-L135).

Each installation still receives the complete app and local playback dependencies. Its own release channel updates its native binary; the operating system maintains the system webview. Couch releases must state their supported webview requirements. The playback computer owns the remote page and API as one release. A permitted update request from a remote page acts on that selected installation; reloading its assets is not a native self-update of the controlling computer. This ownership split follows the agreed one-app contract and is the proposed input to the dependency decision.

## Host authority and remote-page isolation

An external Tauri page cannot use the current Couch UI unchanged. Tauri `2.11.5` injects `window.isTauri = true` before the page scripts, including external pages. JavaScript `isTauri()` reads that flag. It detects the container, not host authority. [Pinned initialization](https://github.com/tauri-apps/tauri/blob/tauri-v2.11.5/crates/tauri/src/manager/webview.rs#L157-L224), [API implementation](https://github.com/tauri-apps/tauri/blob/tauri-v2.11.5/packages/api/src/core.ts).

Couch uses `isTauri()` to choose host credentials, `connection_info`, maintenance acknowledgement, fullscreen behavior, TV presentation and native helpers. Its router also chooses `HashRouter` from this flag. Implementation must identify the trusted bundled local-host context explicitly, route the external UI as a browser remote, and keep metadata/video helpers in the local-host branch. A remote page never receives the local host token. Server-side authority remains the paired Controller or Administrator identity. A presentation flag or query parameter grants no privileges. [App behavior](https://github.com/avoid-quest/couch/blob/34757770ebe02ff5de1ccebb8a68944f35c86968/src/client/App.tsx), [routing](https://github.com/avoid-quest/couch/blob/34757770ebe02ff5de1ccebb8a68944f35c86968/src/client/routes.tsx), [metadata helper](https://github.com/avoid-quest/couch/blob/34757770ebe02ff5de1ccebb8a68944f35c86968/src/client/MetadataEditor.tsx), [video helper](https://github.com/avoid-quest/couch/blob/34757770ebe02ff5de1ccebb8a68944f35c86968/src/client/VideoStage.tsx).

Create the external window under a distinct label without local capabilities or remote grants. Keep host commands constrained to the trusted bundled window/context. Current capabilities grant the `main` window local core/window permissions and define no remote URLs. Tauri's capability model requires explicit remote grants; on Linux it cannot distinguish iframe IPC from top-level IPC, another reason to give the external window none. [Current capability](https://github.com/avoid-quest/couch/blob/34757770ebe02ff5de1ccebb8a68944f35c86968/src-tauri/capabilities/main.json), [Tauri remote access rules](https://v2.tauri.app/security/capabilities/#remote-api-access).

A distinct label alone does not constrain default custom commands from local origins. Use the supported `tauri_build::AppManifest::commands` facility to generate command permissions and grant host commands only to the bundled local window. The current build script has no application command manifest. [Application command permissions](https://github.com/tauri-apps/tauri/blob/tauri-v2.11.5/crates/tauri-build/src/acl.rs#L81-L104), [current build script](https://github.com/avoid-quest/couch/blob/34757770ebe02ff5de1ccebb8a68944f35c86968/src-tauri/build.rs).

The pinned implementation also checks remote origin for application commands when no application ACL manifest exists. Its regression test specifically rejects a remote custom-command invocation. Do not assume older Tauri versions have this behavior. Do not weaken it to make `connection_info` work in a remote page. Source review supports the boundary; native runtime tests still need to prove it for Couch's commands and vendored runtime. [Pinned custom-command guard](https://github.com/tauri-apps/tauri/blob/tauri-v2.11.5/crates/tauri/src/webview/mod.rs#L1819-L1828), [remote-command regression test](https://github.com/tauri-apps/tauri/blob/tauri-v2.11.5/crates/tauri/src/webview/mod.rs#L2420-L2475), [origin/window capability matching](https://github.com/tauri-apps/tauri/blob/tauri-v2.11.5/crates/tauri/src/ipc/authority.rs#L439-L476).

Use Rust `on_navigation` to permit the selected origin's remote routes and deny navigation into bundled/custom-protocol origins or unrelated sites. Handle new windows explicitly with `on_new_window`; deny unexpected popups. Keep target changes in trusted controls. Navigation checks govern document navigation, not all subresources or network requests. Never download target scripts into the local app origin or inject local credentials into the remote page. [Pinned navigation and new-window APIs](https://github.com/tauri-apps/tauri/blob/tauri-v2.11.5/crates/tauri/src/webview/webview_window.rs#L248-L321).

## Startup, switching and recovery

The trusted bundled selector must run before local-backend startup. Current `setup` always spawns the sidecar and starts native services; `connection_info` returns the local host secret. Remote mode needs a lifecycle branch that does neither local playback startup nor host-session initialization. Returning to local mode starts the local installation only after the user selects it. When switching away would interrupt playback or enabled remote control, confirm that interruption as the product contract requires. Persist local state and stop the sidecar and native playback resources before loading the external UI. An idle personal installation needs no interruption prompt. Current process-exit cleanup does not establish a working in-process mode switch. Preserve each installation's state independently. [Native startup](https://github.com/avoid-quest/couch/blob/34757770ebe02ff5de1ccebb8a68944f35c86968/src-tauri/src/lib.rs).

Keep an app-owned Playback device command outside remote-page JavaScript. Tauri supports native menus with Rust handlers and creating/showing/closing windows. A handler can close or hide the remote window and show the bundled selector. Register recovery at app level, or on a window that survives the transition. A page button that invokes a local command would require a remote privilege grant and also disappears on load failure. [Pinned menu/window APIs](https://docs.rs/tauri/2.11.5/tauri/webview/struct.WebviewWindowBuilder.html#method.on_menu_event), [application menu handler](https://github.com/tauri-apps/tauri/blob/tauri-v2.11.5/crates/tauri/src/app.rs).

Couch's current main window is fullscreen without decorations. Qualification must demonstrate that Playback device and Use this computer remain visibly reachable with the supported X11 input devices when the remote page is blank, hung, or unreachable, including appliance sessions without a desktop. Native menu availability is a mechanism, not proof of that experience. A retained local selector/window can provide the fallback; its visibility and focus transitions need a bounded native prototype before implementation is called complete. [Window configuration](https://github.com/avoid-quest/couch/blob/34757770ebe02ff5de1ccebb8a68944f35c86968/src-tauri/tauri.conf.json).

Implement these failure outcomes in trusted controls, with the remote UI handling session errors after it loads:

| Condition | Required outcome |
| --- | --- |
| Target unavailable at startup or later | Retain selected target, retry with bounded backoff, offer another address and Use this computer. Never automatically start local playback. |
| Pairing revoked or missing | Show the selected installation's pairing flow. Native app status adds no role. |
| Old target without desktop-aware remote UI | Explain that this target does not support app remote mode; browser remote remains an option. Offer target update or another target. |
| Target assets/backend mismatch | Reload target assets once per observed build, then show Refresh/update-target guidance without an infinite loop. |
| Target UI requires unsupported web features | Explain app/runtime update requirement and retain local recovery. A load-finished event alone cannot establish application readiness. |
| Restart | Restore chosen mode and target without starting playback. Reconnect only to the chosen target. |

A small explicit target marker is needed before navigation, for example a versioned `desktopRemoteUi` field in existing public `/api/connection`. It means the target UI understands remote mode inside Tauri and needs no native bridge. Perform a bounded, token-free preflight in trusted native code using the existing HTTP client, subject to the selected LAN and redirect policy. This keeps arbitrary LAN access out of the bundled page's CSP. Treat the response as untrusted data. Exact name and schema belong to implementation. Keep the shell entry contract distinct from exact target UI/backend identity. Reject absent or unsupported values instead of assuming every historical browser UI works inside Tauri. The current endpoint exposes name, addresses and player state only; `/api/build` requires authentication, so it cannot alone provide this pre-pairing check. This recommendation adds a bounded entry check, not a new playback protocol. [Current public connection and build endpoints](https://github.com/avoid-quest/couch/blob/34757770ebe02ff5de1ccebb8a68944f35c86968/src/server/hub.ts).

Persist the selected target in local app-owned state, separately from browser-origin pairing storage. Existing remembered connection data lives in `localStorage`, and retries may send the same token to advertised aliases. An origin or installation name does not prove installation identity. Keep credentials scoped to an approved target origin; a changed domain or reused IP needs identity verification or fresh pairing. Do not automatically transfer credentials to arbitrary advertised aliases. Custom domains must resolve to the intended LAN installation; current addresses represent root origins, with no custom path-prefix contract. [Remembered connections](https://github.com/avoid-quest/couch/blob/34757770ebe02ff5de1ccebb8a68944f35c86968/src/client/connection.ts), [alias retry behavior](https://github.com/avoid-quest/couch/blob/34757770ebe02ff5de1ccebb8a68944f35c86968/src/client/session.ts#L59-L67).

Remote mode also needs a separate native update-health path. Current AppImage trial acceptance waits for local frontend acknowledgement, native readiness and backend data/tool checks; the server waits up to 30 seconds for frontend build acknowledgement. A successful remote page load proves none of that local installation health. Recommend shell/native acceptance that can run while the playback backend stays stopped, with exact bundled frontend/sidecar/native identity and local readiness checked before local use. The dependency owner must determine the staged acceptance and deferred-check criteria before rollout. This note does not settle a weaker release gate. [Trial startup checks](https://github.com/avoid-quest/couch/blob/34757770ebe02ff5de1ccebb8a68944f35c86968/src/main.ts), [native update lifecycle](https://github.com/avoid-quest/couch/blob/34757770ebe02ff5de1ccebb8a68944f35c86968/src-tauri/src/lib.rs).

## HTTP, LAN policy and platform limits

External top-level HTTP avoids a bundled page's cross-origin API problem. Couch's bundled CSP currently permits connections only to itself, IPC and loopback, so a bundled remote would need deliberate changes. Tauri applies its configured CSP to bundled assets; the external server owns its page policy. `on_web_resource_request` currently handles the Tauri protocol, not external HTTP responses. Do not treat the bundled CSP as a remote-page firewall. [Couch CSP](https://github.com/avoid-quest/couch/blob/34757770ebe02ff5de1ccebb8a68944f35c86968/src-tauri/tauri.conf.json), [Tauri CSP](https://v2.tauri.app/security/csp/), [resource-request limitation](https://docs.rs/tauri/2.11.5/tauri/webview/struct.WebviewWindowBuilder.html#method.on_web_resource_request).

For the initial Linux target, pinned Wry passes the URL to WebKitGTK `load_uri`; there is no HTTPS-only check in this path. WebKitGTK documents loading URI strings. This supports choosing ordinary HTTP top-level navigation with same-origin `fetch` and `ws`, subject to browser security policy and actual installed WebKitGTK. It does not prove the packaged Debian session works or that every JavaScript API works on an insecure origin. [Pinned Wry Linux loading](https://github.com/tauri-apps/wry/blob/wry-v0.55.1/src/webkitgtk/mod.rs#L369-L375), [WebKitGTK loading API](https://webkitgtk.org/reference/webkit2gtk/stable/method.WebView.load_uri.html).

Host/Origin allowlisting remains necessary on the playback computer; external pages do not bypass it. Couch currently defaults to `0.0.0.0:4100` and checks advertised/known origins. Those checks are not a LAN firewall. The dependency decision must own binding, firewall behavior and the default IP/custom-domain address mechanism. HTTP also provides no transport authentication or encryption. Pairing roles and Tauri capability isolation do not change that accepted initial transport limitation. [Bind default](https://github.com/avoid-quest/couch/blob/34757770ebe02ff5de1ccebb8a68944f35c86968/src/main.ts), [Host/Origin handling](https://github.com/avoid-quest/couch/blob/34757770ebe02ff5de1ccebb8a68944f35c86968/src/server/hub.ts#L258-L327).

WebKitGTK is supplied by the Linux environment; macOS uses WKWebView and Windows uses WebView2. A target update can therefore require a newer browser engine even if the native shell contract stays unchanged. Maintain a tested browser-feature baseline and show update guidance when it is exceeded. [Tauri webview versions](https://v2.tauri.app/reference/webview-versions/).

Later macOS work must qualify ATS exceptions for plain HTTP IPs and custom domains, plus local-network privacy permissions and signed app identity. Apple's documented behavior varies by OS version; an HTTP path on Linux is no evidence of macOS permission or transport support. Windows needs its own installer, WebView2 version, network and recovery qualification. Neither later platform becomes supported by this recommendation. [Apple local networking exception](https://developer.apple.com/documentation/bundleresources/information-property-list/nsapptransportsecurity/nsallowslocalnetworking), [Apple local-network privacy](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy).

## Verification and remaining qualification

This investigation inspected the live product resolution, Couch source, pinned local crate source and matching upstream tags, and current official documentation. Root-task verification used Bun `1.4.2`:

- `bun test tests/frontend-build-identity.test.ts` passed 2 tests and 8 assertions.
- The first targeted hub-test attempt lacked installed dependencies. `bun install --frozen-lockfile --ignore-scripts` installed dependencies without a lockfile change.
- `bun test src/server/hub.test.ts --test-name-pattern 'packaged control connections|advertised|known IP|trial admission'` then passed 14 tests and 67 assertions, with 67 tests filtered out.
- `bun test src/server/hub.test.ts --test-name-pattern 'page deep links|frontend.*trial|acknowledg'` passed 2 tests and 158 assertions, with 79 tests filtered out. This covers private trial acknowledgement and frontend deep links/scripts.

These checks cover existing build generation, build rejection and server admission behavior. No external native window, two-installation update sequence, packaged installer, remote-only startup or T480 deployment was run. The T480 remains an install/run target, never a build host.

Before shipping the recommended design, qualify a bounded matrix on Debian 13 x86_64/X11: older shell with newer supported target and the reverse; missing/unsupported entry marker; same release with different revisions; target update while connected; stale assets; pairing revocation; changed address/domain; refused redirects/popups and local-command attempts; unreachable and hung pages; visible recovery with keyboard and supported remote input; mode switches and restarts with no local backend in remote mode; and update acceptance in each mode. Verify persistent storage across a packaged upgrade. Record the installed WebKitGTK version and packaged build identities.

The dependency owner can proceed with server-delivered UI as the recommended direction. The remaining implementation gates are explicit local-host context, mode-aware native lifecycle and update health, a minimal target-entry contract, trusted recovery controls, and platform qualification. They do not require keeping both installations on the same Couch release.
