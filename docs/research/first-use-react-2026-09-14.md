The lockfile includes Babel core `7.29.7` through shadcn. That transitive CLI dependency does not transform the app. Router loaders, actions and `useFetcher` belong to Data or Framework mode; installing Router alone does not enable them in Couch's declarative router. A data-router migration must also preserve mounted visited pages, browser and native hash routing, and retained search. [React Router modes](https://reactrouter.com/start/modes)

React Compiler has a stable v1 release. Its current integration is a Babel plugin that must precede other transforms; React 19 supplies the compiler runtime. Bun can invoke Babel's `transformAsync` through an `onLoad` plugin, with TypeScript and JSX parsing configured, then accept the transformed source. These official extension points establish a possible integration, not an existing first-class compiler switch in this project. [Compiler release](https://react.dev/blog/2025/10/07/react-compiler-1), [Compiler installation](https://react.dev/learn/react-compiler/installation), [Babel API](https://babeljs.io/docs/babel-core), [TypeScript preset](https://babeljs.io/docs/babel-preset-typescript), [Bun plugins](https://bun.sh/docs/bundler/plugins)

A compiler experiment would need the same plugin in both production builds and `[serve.static]`, plus output inspection and development/production verification. Bun explicitly supports custom static-bundling plugins. No such experiment or render-cost measurement has been performed here. Keep the current build for these fixes; a compiler does not repair incorrect request lifetimes or duplicated state ownership. [Bun static plugins](https://bun.sh/docs/bundler/fullstack#plugins)

Compiler-aware lint can run without compiling the app. Its useful checks include dependencies, hook ordering, render-time ref access, state synchronization and preservation of manual memoization. This is a real gap in the current checks, but a standard TypeScript ESLint installation is not established as compatible: its current documented TypeScript range is `>=4.8.4 <6.1.0`, below Couch's `7.0.2`. Babel's parser can parse TypeScript, but Babel recommends the language's dedicated parser when Babel is not the build and does not support TypeScript through its own rules plugin. Do not add an unsupported parser or change the app compiler solely to obtain lint. A separately verified parser setup or upstream TypeScript 7 support is required before making lint mandatory. [React lint rules](https://react.dev/reference/eslint-plugin-react-hooks), [TypeScript ESLint support](https://typescript-eslint.io/users/dependency-versions/), [Babel ESLint parser](https://babeljs.io/docs/babel-eslint-parser)

## State and API choices

Render should calculate values from existing props and state. User actions belong in handlers; reducers help when several events must preserve the same state invariant, and must remain pure. Effects own synchronization with networks, timers, storage, DOM, native APIs and subscriptions. Reset an entire independent subtree by identity when its state must not survive that identity. Preserve draft edits intentionally instead of mirroring props through an Effect. [React state guidance](https://react.dev/learn/you-might-not-need-an-effect), [Reducers](https://react.dev/learn/extracting-state-logic-into-a-reducer), [Effect synchronization](https://react.dev/learn/synchronizing-with-effects)

All requested core APIs are stable and exported by the installed React: `use`, Suspense, transitions, Actions through `startTransition` or form actions, `useActionState`, `useOptimistic`, `useEffectEvent`, and `useSyncExternalStore`. The local package's exports were checked. `useEffectEvent` became stable in 19.2. Current documentation displays React 19.3, so examples using newer exports must not be assumed to work on this checkout. The current Suspense reference explicitly marks its optional `defer` prop experimental; it is not recommended here. [React 19.2](https://react.dev/blog/2025/10/01/react-19-2), [Suspense](https://react.dev/reference/react/Suspense)

- `use` reads a resource during render. Current guidance explicitly permits a stable client Promise cache. A new Promise per render, including a fresh `.then`, defeats it. Suspense handles pending rendering and Error Boundaries handle rejection; neither automatically adds authorization scoping, invalidation, retry or cancellation. Couch would need cache keys covering origin, credential/installation identity, request parameters and relevant data versions, with bounded retention and explicit refresh. That work is not justified merely to replace its fetch Effects. `cache` and `cacheSignal` are for Server Components, which Couch does not use. [use](https://react.dev/reference/react/use), [cache](https://react.dev/reference/react/cache), [cacheSignal](https://react.dev/reference/react/cacheSignal)
- Transitions schedule nonurgent rendering and expose pending state. They cannot control text inputs and do not guarantee async response order. Keep typed search text synchronous. A transition should be introduced only for a measured expensive result update or an intentional Suspense reveal. [useTransition](https://react.dev/reference/react/useTransition)
- `useActionState` combines action results and pending state and queues action invocations. It can simplify a form whose contract requires sequential submissions, but it is not a universal replacement for abortable latest-query-wins reads or native device selection. `useOptimistic` adds temporary display state during an Action and returns to authoritative state on completion. Couch's queue, playback capabilities and device choice remain server/native authoritative; no measured latency or accepted optimistic contract currently justifies conversion. [useActionState](https://react.dev/reference/react/useActionState), [useOptimistic](https://react.dev/reference/react/useOptimistic)
- `useEffectEvent` fits an external event callback that must read the latest committed values without restarting its subscription. Use it only within that Effect's event logic, not to hide reactive dependencies or wrap user handlers. `useSession`'s navigation callback is a direct candidate. [useEffectEvent](https://react.dev/reference/react/useEffectEvent)
- `useSyncExternalStore` fits a store with a synchronous, immutable snapshot and a subscription that returns cleanup. `useSession` currently owns its WebSocket and React state together; converting it would first require extracting a store, adding complexity without a demonstrated subscriber or consistency benefit. Keep the legitimate connection Effect. [useSyncExternalStore](https://react.dev/reference/react/useSyncExternalStore)

## Concrete gaps and recommended scope

The concern about synchronization is supported by particular paths, not by an Effect count.

1. `App` stores `homeQuery`, `SearchPanel` stores `draft` and fallback query/filter state, and routing owns the committed search. URL changes trigger both parent and child synchronization Effects. The child's Effect reports the query back to the parent. The deliberate distinction is immediate draft versus debounced committed query; establish one owner for each and update the draft owner in input events. Preserve route-driven updates, explicit retries, retained hidden-page search and filter focus. The avoidable work is the post-commit state update and parent notification for a value already supplied by routing. [Derived state and parent notification guidance](https://react.dev/learn/you-might-not-need-an-effect)
2. `SourceSetupDialog` resets controlled tab state in an Effect when opening or changing the requested source. Prefer a fresh dialog-content state boundary or existing shadcn/Radix tab defaults keyed by the requested source. This avoids mounting the previous source form before resetting it. Verify reopening a previously edited source, opening each requested source, query preservation and trigger focus. Keep the existing shadcn components. [Resetting state with a key](https://react.dev/learn/preserving-and-resetting-state)
3. `useSession` assigns `navigation.current = onNavigation` during render solely for a WebSocket event handler. Replace that mirror with `useEffectEvent`. Verify a new callback is used after rerender while the same socket remains connected, and preserve credential-change/unmount cleanup. This removes mutable render-time callback storage and uses the latest committed callback. [Effect Events](https://react.dev/learn/separating-events-from-effects)
4. Retain fetch, native mode, radio expiry, notice timer and focus Effects where they synchronize with external systems. Inspect identity resets separately: keyed ownership can replace blanket resets when all child state belongs to one connection, but remounting a preserved page can lose navigation and focus. `BrowseHome` currently tags loaded results by profile only; the independent correctness audit must verify origin/credential changes as well as profile changes. [Effect lifetimes](https://react.dev/reference/react/useEffect)
5. Search result groups report asynchronous results to their parent through Effects, producing child-to-parent commits. A shared result owner could derive counts, but this is an architectural cost, not an automatic fix. First prove any stale-summary or request bug. Do not add memoization to hide incorrect ownership; no production timing supports a broad performance claim. [React Compiler introduction](https://react.dev/learn/react-compiler/introduction)

For fetch Effects, abort obsolete work and also guard every completion path, including error and final pending updates, against an obsolete lifetime. A transport can finish before abort, and native promises may have no abort facility. Preserve last known results only under the identity they belong to. Ordinary timers and subscriptions need symmetric cleanup. Client cancellation cannot undo a mutation already accepted by the server. Router automatically manages some navigation/fetcher races only when those APIs own the request. [Fetching in Effects](https://react.dev/reference/react/useEffect#fetching-data-with-effects), [Router race conditions](https://reactrouter.com/explanation/race-conditions)

`main.tsx` already mounts root Strict Mode. Verify setup, cleanup, setup on development mounts; duplicate development requests alone are not a production performance finding. Regression coverage should use deferred responses completed in reverse order, identity switches, disconnect/reconnect, unmount cleanup, and the observed DOM or command contract. Keep authorization and update acceptance gates unchanged. [Strict Mode](https://react.dev/reference/react/StrictMode)
