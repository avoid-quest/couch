# Settings

## Two owners

Settings has two owners, each titled with its real name. **This device** (its name) holds what changes only on the device in hand and what it consents to: General, Couch connection, Viewing, Home, Sharing and, in the app, Updates. **The Couch** (its name, "Shared") holds what changes it for everyone: General, Access (Devices, Network), Watching (Playback for the active watching profile, Sources), the Couch's hardware (Sound, Bluetooth, Display, where it has them) and Updates. Each page's eyebrow repeats its owner; shared pages say "· This device" on the host.

Settings opens on This device → General; within a page, frequent settings come first and rare or destructive ones (admin handover, Forget) last. On the TV, Devices opens on Pair a device.

This device → Home's rows: [Home](home.md#home-is-a-timetable).

## Admin-only rows

Every paired device opens every shared page: rows that need an admin say "Only an admin can change this." instead of disappearing, and the server enforces it. Only a device's own consent, its capture, Quit Couch and the first-admin code on the host stay local.

## Section nav

Library and Settings share one section nav: a rail with a check on wide screens and a Select on phones. On the TV, OK on a rail entry opens its page and moves focus to the page's first control.

On the TV, Settings OK enters
the selected page's first enabled control; Back from its content restores the
visible rail entry or narrow Settings page selector, then Home (a source's
own Back first returns to Sources).

## Names, pairings and roles

General owns this device's
name, which is also the name of the server it hosts. An administrator
connected to another host can rename that host in Devices. The Devices list
manages pairings and roles. First run and the pairing dialog: [Shell](shell.md#first-run-names-the-computer).
