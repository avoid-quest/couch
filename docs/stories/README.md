# User stories

What people do with Couch, one story per file, and how far each has got: the
user guide every change keeps true.

## How to write one

A story is one short paragraph at most: a scene from the side of someone using
Couch. Who they are, where, what they do and what they see, in present tense
and in the app's own words, with real UI labels in **bold**
([voice](../product/voice.md): scenes before features).

- **Status**: `idea` (not built), `wip` (partly built, or not in a published
  release), `preview` (in a published preview), `released` (in a stable
  release). The PR that changes it updates it.
- **Good to know** (optional): what someone would trip over today, said plainly.
- **One story per job.** A feature belongs to the one story whose scene needs
  it; others link there. A feature with no story, or a story that repeats
  another, is a finding.
- How Couch works goes in the technical docs; checks and demos go in the PR
  body.

Something new for people to do starts with its story, and the owner agrees it
before the work starts.
