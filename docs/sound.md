# Choose and test TV audio outputs

An administrator opens Settings → Sound to inspect the outputs reported by the Ubuntu user audio session. The page shows readable names, the system default, observed output volume/mute and port availability when the server supplies it. The selected sink name persists in SQLite. Saved selection and the observed native playback route are displayed separately. Choosing an output pins the current native player to `pulse/<sink-name>` and waits for a matching Pulse stream when one exists before saving. It also makes that sink the system default for Ubuntu volume keys and reconciles that default after restart or hotplug. Every later load includes the saved output. Failed selection restores the prior native device and system default where possible.

Stop playback before testing. A test sends three seconds of stereo PCM, a left 440 Hz tone followed by a right 660 Hz tone, to the explicitly chosen output. The waveform peaks at 12% of full scale and includes short fades. Existing output volume and mute still apply. Muted or unavailable outputs cannot be tested. Legacy PulseAudio flat-volume outputs are also refused because creating a test stream could raise their system volume.

Stop sound test is available while the test starts. The server checks the actual test-stream route rather than treating a launched process as success. A wrong or lost observed route stops the test; the test also stops if playback/maintenance starts or the application shuts down. A fixed three-second deadline remains active if the phone disconnects. The idle-update guard remains held until the test stops. No test resumes media or changes the saved playback route, system default, system volume or Couch volume.

Shared playback volume and mute control the selected system sink. Couch holds its native software volume at unity, and reads actual system volume and mute every half second, including changes made with Ubuntu controls or hardware keys. Flat-volume servers are refused to avoid raising the sink level through stream creation. The shared volume is not restored from an old app setting at restart. Settings exposes the saved TV audio delay while idle; it applies to the current item and every subsequent item.

A missing sink, unavailable active port, unexpected route or unreadable audio server interrupts playback. Seekable media pauses; live or still-loading media stops. Late EOF and native error events cannot trigger retries or advance the queue during that interruption. Reconnection or selecting an output never resumes media. Use Resume after the output returns. Linux sets Pulse stream properties `node.dont-reconnect` and `node.dont-fallback` before starting threads so WirePlumber does not rescue the stream onto speakers. Native mpv uses null audio if its explicitly selected device cannot open while the sidecar reports the loss.

An observed route does not establish audible sound. The user must confirm audibility on the actual output. Physical HDMI/analog selection, hardware keys, disconnect/reconnect and session restart remain acceptance gates on [Choose an audio output and test TV sound](https://github.com/avoid-quest/couch/issues/14). Settings also lists available output-only card profiles, including inactive analog and HDMI profiles. Profile activation interrupts playback deliberately, waits for the resulting sink and saves both the stable card name and profile. Errors restore the prior profile and route where possible. Restart/hotplug restores a saved profile when its card reappears, while media remains paused or stopped. Microphone and duplex profile choices are not offered.

## Verification

Source tests also cover profile activation/rollback, retained stable identity, system-volume readback, audio-loss interruption and provider pause acknowledgments. `tests/linux/sound-routing-run.sh` runs the full native Tauri player and a paired remote against disposable PipeWire outputs, including current/subsequent routing, external volume/mute changes, device loss, explicit resume and restart. It requires `pipewire`, `pipewire-pulse` and `wireplumber` in the disposable Ubuntu container.

Source tests cover authorization, idle/current-output admission, muted/unavailable output interpretation, route mismatch, interruption, stale stop requests, controlled PCM and phone controls. `tests/linux/sound-run.sh` runs the production service against two PulseAudio null outputs inside the existing Ubuntu Linux test container. It captures actual samples from the requested output's monitor and checks the test deadline, stop/interruption and preservation of default output and volume. Mount the repository read-only at `/source` and a writable evidence directory at `/artifacts`; the test uses only disposable container audio resources.

This synthetic audio-server run does not establish physical HDMI/analog audibility or the installed PipeWire session. Qualified application/session installation and a coordinated user listening window remain necessary. No microphone capture is used: the synthetic test reads only its null output monitor.

## Supported interfaces

Ubuntu 24.04's [pactl](https://manpages.ubuntu.com/manpages/noble/man1/pactl.1.html) provides JSON sink and stream observations. [paplay](https://manpages.ubuntu.com/manpages/noble/man1/pacat.1.html) supports raw PCM, explicit output, stream name and initial stream volume. Both ship in the appliance's existing `pulseaudio-utils` dependency. PipeWire documents [compatibility with these PulseAudio tools](https://docs.pipewire.org/devel/page_module_protocol_pulse.html). [mpv audio-device](https://mpv.io/manual/stable/#options-audio-device) selects the native output. PulseAudio documents the [PULSE_PROP environment properties](https://wiki.freedesktop.org/www/Software/PulseAudio/Documentation/Developer/Clients/ApplicationProperties/); Ubuntu's WirePlumber 0.4 [linking policy](https://github.com/PipeWire/wireplumber/blob/0.4.17/src/scripts/policy-node.lua) honors `node.dont-reconnect` for explicit targets. Newer [WirePlumber policy](https://pipewire.pages.freedesktop.org/wireplumber/policies/linking.html) also documents `node.dont-fallback`. No privileged audio helper is added.
